# 安全设置说明（v26.11）

适用版本：Code Chat v26.11（前端 Code-Chat-v26.11.html + local_bridge_server v26.11）。
本文档面向部署者与使用者，说明系统各安全层级的配置项、默认行为与加固建议。

---

## 一、安全模型总览

```
外部世界（任意网页/本机进程）
    │
    ▼  X-Bridge-Auth（桥接主 token，首次启动自动生成，CORS *）
┌─────────────────────────────────────────────┐
│  local_bridge_server（127.0.0.1:8765）        │
│  ├─ 统一认证闸门（do_POST 统一 token 校验）     │
│  ├─ SecurityGate（代码静态扫描，T1/T5 档位）   │
│  ├─ AI 审查通道（临时端口 + 一次性 key）        │
│  ├─ EPIP 插件沙箱（独立进程/工作区/资源限制）  │
│  ├─ ai_ork 服务端口（独立 ork_token）          │
│  └─ 任务取消（停止按钮 → 进程组强杀）          │
└─────────────────────────────────────────────┘
    ▲
    │ 本地 HTML 前端（file:// 或本地服务器）
```

设计原则：**所有安全决策 fail-closed**——审查通道异常、令牌缺失、额度耗尽、目标不存在时一律拒绝，不存在默认放行路径。

## 二、令牌体系

| 令牌 | 生成方式 | 持有者 | 权限面 |
|---|---|---|---|
| **桥接主 token** | 首次启动自动生成 `secrets.token_urlsafe(24)`，存 `bridge_config.json` | 浏览器主前端（握手后取得） | 全部桥接 API：终端、文件、聊天存储、插件管理、ai_ork register |
| **AI 审查 key** | 每次审查请求生成 128-bit，随审查端口地址一并交给主前端 | 浏览器主前端（提交 verdict） | 仅本次审查端口 `/review`，一次性焚毁 |
| **ork_token** | 主前端调 `/api/aiork/register` 生成 256-bit | 外部开发者前端 | 仅 ai_ork 指令端口；只能写 `_ork:true` 会话 |
| **插件 RPC 令牌** | 每次插件执行生成 256-bit，经环境变量传给插件子进程 | 插件进程 | 仅当次执行的 RPC 通道，进程结束即失效 |

### 关键配置项（bridge_config.json）

| 键 | 默认 | 说明与安全建议 |
|---|---|---|
| `token` | 自动生成 | **切勿手动置空**。token 为空时所有 API 无认证 + CORS 为 `*`，任意网页可完全控制桥接。若发现被清空，重启桥接会自动重新生成 |
| `security_tier` | `T1` | 代码静态扫描档位。`T1`：仅 warn/block；`T5`：所有可疑代码强制送 AI 审查（需配合可用的审查 LLM） |
| `terminal_enabled` | `true` | 终端总开关。关掉后所有终端调用（含插件 RPC 转发）拒绝 |
| `review_llm_timeout` | `5` | 审查 LLM 调用超时（秒）。审查失败一律按 block 处理（fail-closed） |
| `ai_review_enabled` | `true` | AI 审查通道开关 |

## 三、SecurityGate 与 AI 审查

### 静态扫描（SecurityGate）

对以下代码在**执行前**扫描信号：python、cmd/powershell（终端命令）、插件 Python 源码（含 helper 等非入口文件）：

| 信号类别 | 示例 | 结果 |
|---|---|---|
| 进程创建 | `subprocess`、`os.system`、`getattr(os,"system")`、`eval/exec`、`importlib` 动态加载 | 插件路径直接拦截；终端路径按档位 warn/block/review |
| 凭据窃取 | 读取浏览器 cookie/密码库路径 | block |
| 混淆 | Base64 内嵌可执行内容 | suspicious |
| 下载执行 | 下载后立即运行的模式 | suspicious |

### AI 审查通道

触发条件：档位 `T5` 下的 suspicious/extreme 代码，或审查员配置启用时的指定内容。

流程：桥接开临时端口（127.0.0.1 随机端口）→ 前端把代码+上下文提交给审查 LLM → verdict（allow/block）一次性返回 → 通过后执行，失败一律 block。

**v26.11 修复说明**：审查通道的 HTTP 服务已带 CORS 预检支持（`do_OPTIONS` + `Access-Control-Allow-*`）。此前版本在浏览器环境下 verdict 永远无法提交，审查形同虚设（安全兜底仍在，但审查功能不可用）。

### 插件双层审查

插件 `run()` 触发时：
1. **主脚本静态审查**：合并包内全部 Python 源码扫描，缓存 verdict（同代码免审）
2. **RPC 内部命令审查**：插件内经 `bridge.python/cmd/powershell` 的每条命令单独过 SecurityGate/审查，**fail-closed**

## 四、EPIP 插件沙箱

| 隔离层 | 实现 |
|---|---|
| 进程 | 每次执行独立 Python 子进程，结束即销毁 |
| 工作区 | 独立 `bridge_workspace/plugins/<id>/workspace/`，POSIX 软链拒绝 + 路径白名单 |
| 网络 | RPC 仅 127.0.0.1 + 单次 256-bit 令牌 |
| 资源 | POSIX：CPU/地址空间(512MB)/文件大小/FD 限制；超时后进程组 SIGKILL |
| 结果完整性 | 结果走带外文件（runner 写入+fsync+`os._exit`），插件无法伪造 success |

**已修复的历史问题**（v26.11 已修，旧版本存在）：
- ~~`getattr(os,"system")`/`eval`/`exec` 绕过进程拦截~~（静态审查增强）
- ~~插件 atexit 伪造执行结果篡改 success~~（带外结果通道）
- ~~插件海量 stdout 撑爆桥接内存~~（输出落盘 + 8MB 读取上限）
- ~~审查 claim 可被提前消费销毁~~（未提交 verdict 不 pop）

**残留边界**（已知，低危）：
- 进程级隔离非容器：同用户权限的恶意插件在理论上有逃逸面——只安装来源可信的插件
- Windows 下进程树终止弱于 POSIX（`taskkill /T`）

## 五、ai_ork 服务端口（AI 编排）

架构红线：**Chat 模式不具备工具调用能力**。ai_ork 端口及其创建的会话不提供任何代码/终端/工具执行指令。

| 安全机制 | 说明 |
|---|---|
| 对 Agent 隐藏 | `hidden_from_agent`：提示词不下发、AI 不可 run/list 过滤——AI 无法发现或调用端口 |
| 独立令牌 | ork_token 与桥接主 token 隔离，register 只能由持主 token 的主前端发起 |
| 会话权限边界 | ork_token 只能写 `_ork:true` 会话；用户手建会话只读不可改 |
| 调用额度 | 默认 500 次 call/快照，可调（`quota set`），失败自动退还 |
| 零执行面 | 端口无终端/代码/工具指令；LLM key 只存桥接内存快照，外部前端不可见 |
| 死代码原则 | 插件未安装/未启用时路由 404、前端面板隐藏 |

## 六、前端安全要点

| 项 | 说明 |
|---|---|
| 提示词注入边界 | 插件提示词明确声明"不得覆盖系统规则/用户要求/安全策略"；EPIP 提示词仅注入 Agent/Agent-2 主 AI |
| XSS | 插件列表/会话名等全部 `esc()` 转义 |
| LLM key 存储 | 明文 key 只存浏览器 localStorage，桥接端仅存密文 API 配置；ai_ork 快照为内存驻留，关闭端口即焚毁 |
| 导出/同步 | 聊天数据经桥接存储双写，token 保护 |
| 停止按钮 | abort LLM 流 + 向桥接发任务取消（进程组强杀），审查等待中无进程则安全拒绝 |

## 七、部署加固检查清单

- [ ] `bridge_config.json` 的 `token` 非空（重启自动生成；发现为空立即重启轮换）
- [ ] 只从可信来源获取 `.epip` 包，核对 SHA-256 后再放入 `ai-agent/plugin/`
- [ ] 不需要终端能力时设 `terminal_enabled: false`
- [ ] 敏感环境使用 `security_tier: T5` + 确认审查 LLM 可用（测一条可疑命令能看到 verdict 日志）
- [ ] ai_ork 端口不用时取消勾选插件（路由立即消失）
- [ ] 分发桥接/前端文件时同步公布 SHA-256
- [ ] 旧版本（< v26.11）存在本文档第三节列出的 4 个已修复安全问题，尽快升级
