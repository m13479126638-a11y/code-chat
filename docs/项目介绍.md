# 项目介绍（v26.11）

## 〇、定位声明

**本项目仅供可信环境中的个人开发者使用。**

- "可信环境"：你拥有完全控制权的本机/私有网络，不存在不可信的其他用户或恶意软件
- "个人"：单用户场景，无多租户隔离需求
- 安全模型的设计假设与此定位一致：进程级隔离而非容器、令牌体系防外不防内、fail-closed 兜底但不追求对抗同权限攻击者

在不可信环境（共享机器、暴露端口到公网、运行来源不明插件）中使用，超出本项目的安全承诺范围。

---

## 一、这是什么

一套**本地优先的 AI 对话与编排系统**，两个单文件组件：

| 组件 | 形态 | 职责 |
|---|---|---|
| **Code Chat（前端）** | 单文件 HTML，浏览器打开即用 | 对话界面与编排：四种会话模式、多 AI 成员、上下文工程、工具卡片渲染、插件管理、AI 编排端口控制台 |
| **local_bridge_server** | 单文件 Python，双击运行 | 本地能力桥：终端/网页/文件/屏幕、聊天数据存储、安全审查引擎、EPIP 插件运行时、服务插件路由 |

版本号规则：**年月式**（v26.11 = 2026 年 11 月线），前后端同版本强制配对。

## 三、快速开始

```text
1. 运行 local_bridge_server-v26.11.py → 控制台显示 token
2. 浏览器打开 Code-Chat-v26.11.html → 填 127.0.0.1:8765 + token → 握手
3. 左侧「API 设置」配置 LLM（key 只存浏览器 localStorage）
4. 开聊。需要本地能力时在成员卡片勾选桥接工具；插件在「插件」菜单安装
5. AI 编排端口：安装 ai_ork.epip 并启用 → 「🤖 AI编排端口」面板开放 token 给外部前端
```

## 四、功能与代码实现详解

> 两个组件都是单文件。前端 ~7300 行、桥端 ~4900 行。以下按功能域说明实现位置与关键机制。

### 4.1 前端（Code-Chat-v26.11.html）

#### 会话模型（mkSession / freshState）
- 全局 `S`（设置/会话列表/运行状态）+ 每会话 `ss`（成员/消息流/轮次/暂存/摘要/工作区文件）
- 消息流 `ss.log[]`：每消息一个 entry（speaker/text/round/_thinking/_toolExec/_a2mid 等元数据）
- 与桥接双写：本地 localStorage + 桥接分片存储，`save()` 统一入口

#### 四种模式运行器（runRound 调度）
- `runRound()`：模式分发 + 运行生命周期（S.running、800ms 底部跟随定时器、finally 收尾）
- Chat：无工具纯对话；Agent：任务清单驱动；Agent-2：见下；群聊：多成员轮流

#### Agent-2 单轮 agentic loop（runAgent2Round）
- `while` 循环内：构造 brief（基础上下文+额度标注+loopLog 工具结果回传）→ LLM → parseLead → 分支
- 分支语义：无工具行=本轮结束；工具失败=结束；`询问工具`=结束等 user；成功=loopLog 记录回传继续
- 护栏：`TOOL_STEP_MAX=12`，超限 `hitGuard` 触发自动续轮（最多 6 轮）
- 收尾：中间步打 `_a2mid` 标记、最终步记 `_a2toolCount`，供渲染层聚合折叠

#### 协议解析（parseLead）
- 双语标签（分析/工具/回复 + Analysis/Tool/Reply，大小写不敏感、全角冒号兼容）
- 工具参数：同行 pipe 后内容 + 后续无标签行自动并入（多行代码天然支持）
- 工具名匹配：归一化模糊匹配 + AGENT_TOOLS 别名表（中英均可）

#### 渲染（renderChatOnly / msgNode）
- 全量重建式渲染（innerHTML 清空重填）+ 流式期间 `_streamUpdate` 打补丁
- 消息节点结构：头像 + 元信息 + 思考折叠卡 + 工具汇总折叠卡 + 工具卡 + 气泡
- 折叠体系：`data-act` 事件委托（think/tool/toolsum/file），状态存 entry 持久化
- 跟随滚动：`chatStick` 状态 + 800ms 轮询（尊重用户上翻）；`#chat { scroll-behavior: auto }` 消除 smooth 竞争

#### 桥接同步（bridgeLoadSession / bridgeLoadOlder）
- 打开仅桥端会话时只拉最新分片；往上翻按需拉更早分片；导出前自动拉齐全部
- `_bp.loadedFrom` 游标管理分片位置

#### 工具实现（ToolImpl）
- 浏览器内：JS计算/正则/JSON/统计/函数图像（SVG）/写文本/文件编辑/Pyodide Python
- 桥接类：网页抓取/历史查询/本地桥接（终端直达语法 `工具: python|代码`）
- 询问工具：普通工具队列成员，调用后 loop 结束等 user

#### LLM 调用（callLLM）
- 双回调流式（正文 chunk + thinking chunk）、AbortController 停止、思考预算

#### AI 编排端口面板（_renderAiorkPanel / _aiorkRegister）
- 检测 ai_ork 插件启用状态（死代码原则：未启用卡片隐藏）
- register 推送服务商 key/base 快照换 ork_token；token 仅内存展示，刷新即轮换

### 4.2 桥端（local_bridge_server-v26.11.py）

#### HTTP 服务与认证
- `BridgeHTTPRequestHandler`：8765、POST 统一 token 闸门（handshake/心跳除外）、CORS `*`+`X-Bridge-Auth`
- GET 各端点逐一 token 校验；`/api/aiork/*` 在统一闸门之前分流（自带 ork_token 鉴权）

#### 终端工具（tool_terminal）
- argv 前缀防注入、工作目录限定（resolve_confined）、超时进程组强杀、取消（_ACTIVE_TASKS）
- 输出走临时文件 + 限量读取（内存恒定）；执行历史 exec_history 三动作（last/get/search）

#### 安全引擎
- `security_gate`：多信号扫描（进程创建/凭据窃取/混淆/下载执行）+ `tier_decision`（T1～T5 档位）
- AI 审查：临时端口 + 128-bit key + CORS 预检、verdict 一次性、fail-closed
- 插件双层审查：主脚本合并源码审查（缓存）+ RPC 内部命令逐条审查

#### EPIP 插件运行时
- 扫描/解包（路径白名单/符号链接拒绝/大小限额）→ 清单校验 → 启用状态管理
- `_plugin_precheck` 静态审查 + `_plugin_execute`：独立子进程/最小 env/资源限制/单次 RPC 令牌
- 结果完整性：runner 写带外结果文件 + fsync + `os._exit`（防 atexit 伪造）；hidden 插件三链路隐身

#### AI 编排端口（_aiork_*）
- `_aiork_active()` 启用闸门（死代码原则核心）；`_aiork_http` 分发 register/exec
- 16 条指令：会话 CRUD（agent_data_save 双索引，前端立即可见）/消息流/LLM 调用写回/额度/token 轮换
- `_ork:true` 会话权限边界：ork_token 只能写自建会话，用户会话只读

#### 聊天存储
- `chats_index` 目录索引 + manifest 元数据 + JSON 完整数据 + log 分片（前端按需加载）
- `agent_data_save/load/delete` 为会话 CRUD 统一入口

#### 任务取消
- `_task_register/bind/take_cancelled/task_cancel` + `POST /api/task/cancel`（前端停止按钮联动，进程组 SIGKILL/taskkill）
